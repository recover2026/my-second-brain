# 本库与专家包怎么分工

## 一句话判据

> **外部查得到的 → 专家包；只有你知道的 → 本库。**

政策文号、条款费率、行业案例、制度原文，这些别人也能查到，进专家包；
你踩过的坑、被怼回来的教训、对某件事的定论、你偏好的表达方式，这些**只有你知道**，进本库。

## 决策树：该去哪查

```
要回答一个问题
├─ 问的是「事实是什么」
│   ├─ 政策/条款/制度/行业案例 → 专家包 02–14 号库（见 [[农险专家包 14 库速查地图（含绝对路径）]]）
│   ├─ 某个工具/脚本在哪       → [[本机 60+ Skills 速查与选型]]
│   └─ 桌面那个文件叫什么       → [[桌面在办资产清单（2026-09-27 实测扫描）]]
│
└─ 问的是「我以前怎么定的 / 该怎么干」
    ├─ 交付前该过哪些关   → [[交付前必过的质量门禁（MOC）]]
    ├─ PPT 怎么做才算好看 → [[PPT 必须"真国风 + 少码字 + 结构多样"]]
    ├─ 标书怎么审         → [[PPT与遴选标书必须"全量OCR + 逐页逐部分目检"]]
    └─ 不确定属于哪类     → 先搜本库，搜不到再判断是不是该落一条新的
```

## 决策树：该往哪存

```
要存一条东西
├─ 它是我从公开渠道能查到的事实吗？
│   └─ 是 → 不进本库。走专家包 `00-用户反馈消化台账.md` 的六步并入流程
└─ 它是我的判断/经验/踩坑/偏好吗？
    └─ 是 → 进本库 01-经验层，写清 why（为什么存）和 source（从哪来）
```

**最常犯的错**：把"某省遴选评分办法第 X 条"抄进本库。那是外部事实，专家包 08 库里就有，
抄过来只是多一份会腐烂的副本。**本库只留你读完之后得出的打法**。

## 现状：单向关联（2026-09-28 实测）

| 方向 | 通不通 | 依据 |
|---|---|---|
| 本库 → 专家包 | ✅ | 有 [[农险专家包 14 库速查地图（含绝对路径）]]，且刷新器会扫它的 references 目录 |
| 专家包 → 本库 | ❌ | 专家包全目录 grep「我的知识库」**零命中**，它不知道本库存在 |
| 农险会话里自动查本库 | ⚠️ | 只靠用户级记忆里一段（**每轮会被截断**），不稳定 |

**这是刻意的选择，不是疏漏**：专家包升级会被整体覆盖，往里写等于白写。
所以走**单向监听**：本库只读专家包，感知变化、提建议，改不改由你定。

## 联动三件套

| 动作 | 命令 | 产出 |
|---|---|---|
| 拍基线 | `python3 _工具/专家包联动.py snapshot` | `data/expert_baseline.json` |
| 查变化 | `python3 _工具/专家包联动.py check` | [[专家包变更与同步待办]] |
| 提意见 | `python3 _工具/专家包联动.py advise` | [[对专家包的提升建议（待用户拍板）]] |

**提意见的规矩**：只提不改。你拍板采纳后，走专家包自己的通道——
登记到 `references/00-用户反馈消化台账.md`，按 `references/00-用户反馈消化并入模版.md` 六步流程执行。
别绕过它的流程直接改文件，那样升级时会被覆盖掉。
