## 起因

要把本地知识库做成永久网站，第一反应是 `git push` 到 GitHub Pages。
实测下来发现这台机器的网络是"半通"的：

| 目标 | 结果 |
|---|---|
| `github.com:443`（git https 端点） | **不通**（curl 000，nc 失败） |
| `github.com:22`（SSH 端点） | **通** |
| `api.github.com` | **通**（200） |
| `codeload.github.com` | 通（301） |

## 铁律

> **发布 / 上线 / 拉代码之前，先花 30 秒探通道，再决定走哪条路。**

探什么：`curl -o /dev/null -w "%{http_code}"` 看站点、`nc -z -G 6 域名 443/22` 看端口、
`ls -la ~/.ssh` 看有没有钥匙。别等脚本失败了才发现路是断的。

## 三条可用路径（按推荐顺序）

1. **API 通道（最省事）**：只碰 `api.github.com`，用 Git Data API 建 blob→tree→commit→ref，
   再用 `POST /repos/{o}/{r}/pages` 开 Pages。不需要 SSH 钥匙，也不需要 443。
   → 已固化成 `_工具/发布到GitHub.py`。
2. **SSH 通道**：22 通，但没有 `~/.ssh` 钥匙；要用户先 `ssh-keygen` 并把公钥贴到 GitHub。多一步人工。
3. **443 通道**：本机不可用，别再试。

## 坑 2：空仓库用不了 Git Data API

项目新建的仓库**默认是空的**（无 commit、无 ref）。这时直接 `POST /repos/{o}/{r}/git/blobs`
会被拒：**409 Git Repository is empty.**

解法：先用 contents API 写一个小文件造出首次提交，把仓库"激活"，之后 Git Data API 一切正常。

```python
PUT /repos/{o}/{r}/contents/README.md   {"message":"init","content":"<base64>"}
```

顺带两条：

- **别硬编码 `main`**：用 `GET /repos/{o}/{r}` 里的 `default_branch`，用户的默认分支可能是 master。
- 两次都踩在同一个根上——**想当然**。以为"能建仓库就能传文件"，实际中间还有个状态叫"空"。

## 顺带记住

- 免费账户开 GitHub Pages **必须公开仓库**（私有仓库要付费计划）→ 内容会被 clone，
  所以发布包要单独生成，只放内容、不放 `_工具/` `_收件箱/` 这类本机脚本。
- 发布包注入 `<meta robots noindex>` 防收录，属"低成本加一道锁"。
